All the features below are **opt-in** and **default-OFF**. None of them adds a
hard dependency: with the rest of Agora absent, each one degrades to its default
and authz keeps working standalone with unchanged behavior.

## Organization as tenant

When the app turns tenancy on in `@adonis-agora/context` (`tenancy: { enabled: true }` in
`config/context.ts`), authz scopes every check to the active tenant (for authkit apps, the
active organization) with no authz config:

```ts
// The request's active organization is "acme"
await authz.can(user, 'posts.edit')                              // checked in acme
await authz.can(user, 'posts.edit', { scope: { tenantId: '' } }) // global, explicitly
```

An explicit `scope`, a `tenant` resolver or `resolveTenant` still wins. Inside
`Context.allTenants()`, outside a request, or with no active tenant, checks run in the
global scope as before.

### Org roles as authz roles

Map the caller's role inside the active organization (authkit's `orgRole`, or the `role` your
app passes to `Context.setTenant`) to authz roles. They apply in that organization only, and only
to the user making the request:

```ts title="config/authz.ts"
export default defineConfig({
  default: 'lucid',
  stores: { lucid: stores.lucid() },
  tenancy: {
    roles: { owner: 'org_admin', admin: 'org_admin', member: 'org_member' },
  },
  roleGrants: {
    org_admin: ['billing.*', 'members.*', 'posts.*'],
    org_member: ['posts.read'],
  },
})
```

Mapped roles join the user's effective roles like `resolveRoles` does, so `roleGrants` gives them
their permissions. Unmapped org roles grant nothing.

| `tenancy` key | Default | |
| --- | --- | --- |
| `enabled` | `'inherit'` | follow `config/context.ts`; `true`/`false` forces it |
| `kinds` | context's `kinds` | tenant kinds authz honours; with nested tenants (clinic → unit) the innermost level of one of these kinds is used |
| `family` | — | use the tenant of this family when a request carries more than one |
| `roles` | — | tenant role → authz role(s) |

`tenancy: false` keeps authz global even when context turns tenancy on.

### Consoles: who sees every organization

`authorizeByRoles` takes `allTenants`: a viewer holding one of those roles globally (or a
`superAdminRoles` role) sees every organization in a console; everyone else it allows sees their
own:

```ts title="config/durable.ts"
authorize: authorizeByRoles({ roles: ['ADMIN', 'org_admin'], allTenants: ['ADMIN'] }),
```

## Tenant auto-scope

When a permission check gets no explicit tenant and your `tenant` resolver
yields none, default the tenant to the active Agora context's `tenantId`.

`resolveTenant` is a **function** — `() => string | undefined` — called on every
check that still has no tenant. The package ships one ready to use,
`tenantFromContext`, which reads the active Agora context's `tenantId`:

```ts title="config/authz.ts"
import { defineConfig, stores, tenantFromContext } from '@adonis-agora/authz'

export default defineConfig({
  default: 'lucid',
  stores: { lucid: stores.lucid() },
  resolveTenant: tenantFromContext,
})
```

Any zero-argument function works, so you are never tied to the Agora context —
read the tenant from wherever your app already keeps it:

```ts title="config/authz.ts"
import { HttpContext } from '@adonisjs/core/http'

export default defineConfig({
  // ...
  resolveTenant: () => HttpContext.get()?.request.header('x-tenant'),
})
```

Precedence: explicit `scope` arg → `tenant` resolver → `resolveTenant`. With
`resolveTenant` unset (the default), no context means the global `''` scope, as
before.

## Global-role bridge

Bridge an auth provider's **global roles** — the ones authkit puts on the active
Agora context — into authz checks at check time, with nothing seeded in the
database.

```ts
defineConfig({
  // A user holding one of these global roles is allowed everything.
  superAdminRoles: ['platform:super'],
  // Role → permissions/wildcards, unioned into permission checks.
  roleGrants: {
    auditor: ['audit.*'],
  },
})
```

A super-admin global role short-circuits every decision — `can`, `hasRole`,
`hasAnyRole` and `scope` — to allow. Otherwise, the permissions `roleGrants`
maps onto the user's **effective** roles are unioned with the store's grants and
the whole set goes through the wildcard matcher.

`roleGrants` applies to the user's *effective* roles — the context claim, the
`resolveRoles` seam and the store alike — so it is not limited to global ones.
See [Effective roles](/docs/authz/config#effective-roles-resolveroles--rolegrants)
for the full model, and [Roles](/docs/authz/roles#superadminroles--global-roles-that-allow-everything)
for how `superAdminRoles` composes with the `superAdmin` hook.

## Reading the context yourself

The two features above are built on a small set of readers the package exports,
and you can use them for your own wiring. Each one degrades to a safe default
when the Agora context is not there, so calling them is never conditional:

```ts
import {
  globalRolesFromContext,
  readContextValue,
  subjectRefFromContext,
  tenantFromContext,
} from '@adonis-agora/authz'

tenantFromContext()       // the active tenant id, or undefined
subjectRefFromContext()   // the request caller, e.g. { type: 'user', id: '42' }, or undefined
globalRolesFromContext()  // the caller's global roles, or []
readContextValue('locale') // any other key the context carries, or undefined
```

| Export | Returns | Without a context |
| ------ | ------- | ----------------- |
| `tenantFromContext()` | The active tenant id. | `undefined` |
| `subjectRefFromContext()` | The request caller's ref. | `undefined` |
| `globalRolesFromContext()` | The caller's global role names. | `[]` |
| `readContextValue(key)` | Any value the context carries. | `undefined` |
| `readContextAccessor()` | The context accessor itself. | `undefined` |
| `AGORA_CONTEXT_ACCESSOR` | The symbol the accessor is published under. | — |

`tenantFromContext` is the reader you pass straight to `resolveTenant`;
`superAdminRoles` and the effective-role union use the global roles only for
the subject `subjectRefFromContext()` names: a request made by an admin never
gives ADMIN to another user it asks about. Reach for `readContextAccessor` / `AGORA_CONTEXT_ACCESSOR` only
when you are writing something that publishes or replaces a context — a test
harness, for example.

## Event-driven provisioning

`defineAuthzProvisioning` subscribes to authkit's diagnostics events (via the
**optional** `@adonis-agora/diagnostics` peer) and runs config-mapped actions
against the store. It is best-effort — actions never throw into the host, and a
missing diagnostics package is a no-op.

```ts title="start/authz_provisioning.ts"
import { defineAuthzProvisioning } from '@adonis-agora/authz/provisioning'
import authz from '@adonis-agora/authz/services/main'

await defineAuthzProvisioning({
  store: authz.store,
  on: {
    'organization.created': (ev, store) => {
      if (!ev.accountId || !ev.orgId) return
      return store.assignRole({ type: 'user', id: ev.accountId }, 'org:owner', {
        tenantId: ev.orgId,
      })
    },
    'member.added': (ev, store) => {
      if (!ev.accountId || !ev.orgId) return
      return store.assignRole({ type: 'user', id: ev.accountId }, 'org:member', {
        tenantId: ev.orgId,
      })
    },
  },
})
```

Keys are the bare authkit event type (subscribed on channels
`agora:authkit:<type>`). The call returns a handle with `.stop()` to
unsubscribe.

<Callout type="warn">
  **Read the ids from the top level of the event, not from `metadata`.** authkit
  redacts its audit event before publishing it on the diagnostics bus: `email`,
  `ip` and the free-form `metadata` are stripped, and what reaches a subscriber is
  the event `type` plus the opaque `accountId`, `actorId`, `clientId` and `orgId`.
  An action written against `ev.metadata.orgId` reads `undefined` in production.
  `metadata` survives only when the host feeds the bus itself, or wires
  `defineAuthzProvisioning` to authkit's un-redacted `events.onEvent`.
</Callout>

## The `/authz/can` endpoint

`registerCanEndpoint` registers a route that answers a permission check for the
active user. Optional peer: `@adonisjs/core` (router types — already a peer).

```ts title="start/routes.ts"
import router from '@adonisjs/core/services/router'
import { registerCanEndpoint } from '@adonis-agora/authz/http'
import authz from '@adonis-agora/authz/services/main'

registerCanEndpoint(router, { service: authz }) // default path: /authz/can
```

<Callout type="info">
  **Contract (the frontend depends on this exactly):**

  - Request JSON: `{ "permission": string, "resource"?: string }`
  - Response JSON: `{ "allowed": boolean }`

  An anonymous/unmappable user or a missing `permission` yields
  `{ "allowed": false }`.
</Callout>

Override the path and user resolution as needed:

```ts
registerCanEndpoint(router, {
  service: authz,
  path: '/api/authz/can',
  resolveUser: (ctx) => ctx.auth?.user,
})
```
