## Requirements

- Node.js 24 or newer (tested on Node 24 and 26).
- Every `@adonis-agora/*` package on 1.x. `@adonis-agora/authz-react` 1.0 accepts
  `@adonis-agora/authz` up to `<2.0.0`, and `@adonis-agora/authz` 1.0 accepts
  `@adonis-agora/diagnostics` up to `<2.0.0`.

```sh
pnpm add @adonis-agora/authz@^1 @adonis-agora/authz-react@^1
```

## Subject pivot tables are no longer renamed at boot

The two subject pivots are `authz_subject_role` and `authz_subject_permission`, with the columns
`subject_type` and `subject_id`. authz 1.0 only reads those names. A database that still has
`authz_user_role` / `authz_user_permission` (or `user_type` / `user_id` columns) is no longer
converted for you when the app boots: authz creates new, empty `authz_subject_*` tables next to
the old ones, and every subject loses its roles and direct permissions.

If your database already has the `authz_subject_*` tables, there is nothing to do.

Otherwise, rename them with a migration **before** you deploy 1.0.

Before, booting the app was enough:

```sh
node ace serve   # authz renamed authz_user_role → authz_subject_role on its own
```

After, add a migration and run it:

```ts title="database/migrations/xxxx_rename_authz_subject_pivots.ts"
import { BaseSchema } from '@adonisjs/lucid/schema'

const PIVOTS = [
  ['authz_user_role', 'authz_subject_role'],
  ['authz_user_permission', 'authz_subject_permission'],
] as const

export default class extends BaseSchema {
  async up() {
    this.defer(async (db) => {
      for (const [from, to] of PIVOTS) {
        if (!(await db.schema.hasTable(from))) continue
        if (await db.schema.hasTable(to)) {
          throw new Error(`Both ${from} and ${to} exist: copy the rows by hand (see below)`)
        }
        await db.schema.renameTable(from, to)
        await db.schema.alterTable(to, (table) => {
          table.renameColumn('user_type', 'subject_type')
          table.renameColumn('user_id', 'subject_id')
        })
      }
    })
  }

  async down() {
    this.defer(async (db) => {
      for (const [from, to] of PIVOTS) {
        if (!(await db.schema.hasTable(to))) continue
        await db.schema.alterTable(to, (table) => {
          table.renameColumn('subject_type', 'user_type')
          table.renameColumn('subject_id', 'user_id')
        })
        await db.schema.renameTable(to, from)
      }
    })
  }
}
```

```sh
node ace migration:run
```

<Callout type="warn">
  If the app already booted against this database with authz 0.15 or newer while the old tables
  were still there, both `authz_user_role` and `authz_subject_role` exist. Copy the rows from the
  old table into the new one (`INSERT INTO authz_subject_role (subject_type, subject_id, role_id,
  tenant_id) SELECT user_type, user_id, role_id, tenant_id FROM authz_user_role`, and the same for
  `authz_user_permission` with `permission_id`), check them, then drop the old tables.
</Callout>

If you override the table names through `tables` in `config/authz.ts`, use your names in the
migration. If your own tables still have `user_type` / `user_id` columns, rename only the
columns.

## `requireRole` and `authorizeByRoles` read `ctx.auth.user` only

The route middleware and the dashboard `authorize` helper get the signed-in user from your
`@adonisjs/auth` guard. They no longer call `ctx.auth.getUser()`. When no auth middleware ran
on the route, they call `ctx.auth.check()` themselves, so a session is picked up on demand. An
`auth` object that only has `getUser()` counts as signed out: the route answers `401` (or
`guestRedirect`) and the dashboard denies with `unauthenticated`.

Before, `ctx.auth` could be any object with a `getUser()` method:

```ts title="app/middleware/auth_middleware.ts"
export default class AuthMiddleware {
  async handle(ctx: HttpContext, next: NextFn) {
    // a custom ctx.auth that requireRole read through getUser()
    ctx.auth = { getUser: () => resolveSessionUser(ctx) }
    return next()
  }
}
```

After, `ctx.auth` is the `@adonisjs/auth` authenticator. Routes and dashboards need nothing
else: authz authenticates on demand.

```ts title="start/routes.ts"
import { middleware } from '#start/kernel'

router
  .get('/admin', [AdminController, 'index'])
  .use(middleware.requireRole({ roles: ['ADMIN'] }))
```

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@adonis-agora/telescope/ui'
import { authorizeByRoles } from '@adonis-agora/authz'

export default defineConfig({
  authorize: authorizeByRoles({ roles: ['ADMIN'] }),
})
```

You don't need a global `silentAuth` in `router.use` just for authz. Keep your own `auth` or
`silentAuth` middleware where the rest of your app needs it.

## Token roles count only for the user who made the request

The global roles in the request's token (written into the Agora context by authkit) now count
only for that user. When your code asks about another user in the same request, that user gets
their own app and store roles, never the caller's.

Before, an admin listing users saw everyone as `ADMIN`:

```ts title="app/admin/controllers/users_controller.ts"
import authz from '@adonis-agora/authz/services/main'

export default class UsersController {
  async show({ params }: HttpContext) {
    // an admin is signed in; the researcher only has RESEARCHER in the database
    return authz.effectiveRoles({ id: params.id }) // ['ADMIN', 'RESEARCHER']
  }
}
```

After, the same call returns only that user's roles:

```ts
return authz.effectiveRoles({ id: params.id }) // ['RESEARCHER']
```

If you write `globalRoles` into the Agora context yourself, also write the `userRef` of the user
they belong to (`{ type: 'user', id }`). Roles with no `userRef` apply to nobody.

## Sharing the signed-in user with React

`@adonis-agora/authz` exports `resolveAuthUser(ctx.auth)`, which returns the signed-in user and
authenticates on demand. Use it in the Inertia share so it works on pages without an `auth` or
`silentAuth` middleware.

Before:

```ts title="config/inertia.ts"
authz: (ctx) => buildAuthzShare(authz, ctx.auth?.user ?? null),
```

After:

```ts title="config/inertia.ts"
import { resolveAuthUser } from '@adonis-agora/authz'

authz: async (ctx) => buildAuthzShare(authz, await resolveAuthUser(ctx.auth)),
```

## Ace commands renamed

The ace commands follow `authz:<noun>:<verb>`. The old names are gone, with no alias:

| Before | After |
| --- | --- |
| `authz:grant <role> <permission>` | `authz:roles:grant <role> <permission>` |
| `authz:assign <role> <subjectId>` | `authz:assignments:add <role> <subjectId>` |
| `authz:list` | `authz:roles:list` and `authz:permissions:list` |

Update scripts, seeders and deploy steps that call them. The arguments and the `--type` / `--tenant`
flags are the same. See [CLI](/docs/authz/cli) for the new commands.
